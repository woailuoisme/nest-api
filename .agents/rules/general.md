# 通用准则

1. **语言**：分析、解释、文档、总结一律简体中文；代码、标识符、commit message 保持原文。
2. **表达**：直入结论，不寒暄、不复述用户已知信息。
3. **先对齐再动手**：需求模糊、缺少上下文或存在多方案时，先给利弊并确认，不臆测。
4. **最小变更**：只改与任务直接相关的代码；顺带发现的无关问题只报告，不擅自修改。
5. **闭环交付**：改完依次跑格式化、静态检查、测试（本项目 `just check`），全绿才算完成。
6. **提交**：commit message 遵循 Conventional Commits（`feat:` / `fix:` / `refactor:` / `test:` / `chore:`）；未经明确要求不提交、不推送。
7. **引用**：提及文件或符号用可点击链接，如 `[name](file:///abs/path#L10-L25)`。
8. **终端纪律**：见 `shell.md`；工程细则（假设、简化、AST 改写）见 `coding-discipline.md`。
